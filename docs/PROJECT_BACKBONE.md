## 2. 总体架构

- 发行形态是一个客户端 mod ID、一个客户端入口、一个 JAR；各功能作为源码级内部模块维护，不做嵌套 JAR 外壳。
- 总控使用原生 Minecraft `Screen`，不引入 WebView、Cloth Config 或 YACL；Mod Menu 只能作为可选入口。
- 内部模块之间通过清晰的 provider/bridge 边界连接；外置模块存在且桥接兼容时，外置模块优先。
- 外置模块接管后，内置对应模块必须零初始化：不构造控制器、不注册事件、不启动线程、不读写对应配置。
- 所有复杂工具都必须保留父 Screen；关闭、Esc 和返回应恢复同一父 Screen。父上下文失效时安全返回游戏并给出一次提示。

## 3. 总控与 UI 固化要求

- 左侧固定导航顺序：总览、奥术 HUD、卷轴计算、饰品配装、发酵与厨具、SIMMC 网页地图、预留板块、工具组按键；诊断与日志固定在底部。
- 总览必须说明鼠标入口、快捷键、外置模块接管和当前运行状态。
- 总控和子页面使用中文；长警告、状态和按钮文字必须在不同 GUI 缩放与分辨率下可读、不截断、不重叠。
- 工具组按键进入专属设置页，不跳转 Minecraft 原生控制页；专属页显示当前键、修改、恢复和冲突提示。
- 鼠标点击是与快捷键并行的完整入口。快捷键不得拦截按钮点击、滚轮、拖动物品、容器交互、地图操作或原生 Screen 返回。
- 容器名称、聊天和 HUD 信息不能互相遮挡；发酵/厨具提示使用右上角区域，不再占用聊天左下角。

## 4. 快捷键与输入边界

默认组合键如下：

| 组合键 | 功能 |
| --- | --- |
| `\` + `1` | 奥术 HUD |
| `\` + `2` | 卷轴计算 |
| `\` + `3` | 饰品配装 |
| `\` + `4` | 发酵与厨具 |
| `\` + `5` | SIMMC 网页地图 |
| `\` + `` ` `` | 诊断与日志 |
| 主键盘 `0` | 饰品工具直达 |

- 按住前缀键后在约 650-800 ms 窗口内按次键；单独松开前缀键打开工具组按键页。
- 默认键暂不使用 F1-F12、Insert/导航区、SysRq、小键盘和方向键；玩家重绑定时可以选择这些区域。
- 文本框、聊天、命令、书、告示牌和其它编辑界面聚焦时，组合键完全旁路，不吞字符。
- 超时、Esc、未知次键、失焦、切屏和全部鼠标事件都应清除前缀状态并放行原生行为。
- 冲突提示只说明工具组内部冲突；重绑定不能破坏鼠标入口。

## 5. 内置模块与外置桥接

### 5.1 奥术 HUD

- 使用已获得许可的 Simes 功能范围，只实现奥术冷却/吟唱/持续状态 HUD。
- 服务器消息和 BossBar 是状态来源；显示位置为左上角。
- 仅在规范化地址为 `play.simmc.cn` 时激活；离服、切服或客户端停止时清空状态。
- 检测到外置 Simes 时，内置 HUD 不初始化，由外置版接管。

### 5.2 发酵与厨具

- 发酵提示和厨具提示是两个独立开关，默认开启。
- 仅在 `play.simmc.cn` 激活；点击目标方块后，根据服务器可见消息显示状态，不伪造没有收到的数据。
- Simes 授权范围不包括市场、估值、余额、自动消息和 Mana 功能。

### 5.3 mod 3 饰品配装

- 内置饰品工具可从背包或容器扫描、复核、编辑、评分和计算配装。
- 外置桥接 ID：`simmc_travel_hunter_accessory_tool:screen_opener_v1`，协议为 `Consumer<Screen>`。
- 外置维护版存在时优先接管；独立入口和 Tool Set 入口都必须保留。
- mod 3 `6.1.0-fabric` 的独立桥接实现仍需重新确认真实构建、提交和客户端联调状态，不得仅凭线程描述宣称已发布。

### 5.4 mod 4 卷轴计算

- 内置卷轴计算保留原 solver、材料排除、帮助、关于、取消、设置和独立入口行为。
- 外置桥接 ID：`simmc_arcane_scroll_calculator:screen_opener_v1`，协议为 `Consumer<Screen>`，使用 `ObjectShare.putIfAbsent`。
- 已知外置桥接版本为 `2.1.0-fabric`，提交 `d433748aa7a16964d0e9aa7de9d283d12c800b92`；真实标题/世界打开和父 Screen 恢复仍需整合客户端验收。

## 6. SIMMC 网页地图与 Xaero

- 地图板块位于发酵与厨具下方，默认组合键为 `\` + `5`。
- 已取得 SIMMC Map 授权并有仓库：`https://github.com/MurphyPotato/SIMMC-Xaero-Map`；本地源文件位于 `I:\mc smc服\simmc moster hunter 2.0\simmc-tool-set_project\子版块源码or源文件or接口\SIMMC-Xaero-Map-main`。
- 已验证运行组合：Xaero World Map `1.39.13` + Xaero Minimap `25.2.16`，Minecraft 1.21.8 Fabric。
- 两个 Xaero 都存在且版本不匹配时：显示“版本不完全兼容，可能启动失败，且可能导致游戏崩溃”的警告，并继续尝试运行地图子模块；失败时只停用地图，不得影响其它模块。
- 缺少任一 Xaero 时显示缺失警告，地图实现不启动；其它子模块继续运行。
- 独立 SIMMC Map 已安装时由独立版接管，整合包不得重复加载内部地图实现。
- SIMMC 覆盖层同时面向 Xaero 世界地图和小地图；缩放、拖动、点击和鼠标归属仍由 Xaero 处理。
- 地图连接、刷新、公开标记、切服/离服清理和运行失败状态必须在地图页和诊断中可见。
- Xaero 与 Mod Menu 外部 JAR 不打包进 Tool Set；`jsoup 1.18.3` 作为构建所需嵌入依赖保留。

## 7. 配置、诊断与隐私

- 新配置写入 `config/simmc-tool-set/`；旧配置只在新文件不存在且对应外置模块未安装时一次性只读导入，不修改、删除或双向同步旧文件。
- 诊断记录默认只保存在内存，玩家点击导出后写入 `config/simmc-tool-set/diagnostics/`；页面显示最近文件路径并支持复制。
- 不自动上传诊断、截图、凭据、玩家数据或设备标识；不加入遥测和不受控网络通信。
- 地图只访问已授权的数据源；所有后台线程、HTTP 客户端、求解器和状态缓存必须在切服、离服和客户端停止时关闭或清空。

## 8. Git、构建与发布

- 每次功能迭代建立新版本号、独立分支和独立标签；不覆盖旧代码、旧 JAR、旧标签、旧 Release 或旧资产。
- 可分发 JAR 放在项目根的 `release/` 外部目录，不放入 Git 工作树；旁边必须有同名 `.jar.sha256`。
- 发布前至少完成：完整构建、兼容性 smoke、JAR 静态审计、客户端专用审计、版本/依赖审计和工作树检查。
- PowerShell 中使用项目 JDK 21 和 Gradle wrapper；Loader 参数必须使用脚本的明确参数形式，不能让 `-Ploader_version` 被解析成 `0`。
- 构建或测试失败时先记录完整错误和环境，区分依赖下载、Gradle worker、编译、运行时和断言问题，不得把部分成功写成整体成功。

## 10. 问题与解决方案记录

- 初始启动问题：Mixin 类边界过宽会让入口类被误判；通过收窄 Mixin 包路径修复，并保留客户端专用审计。
- Gradle 发行包未缓存时，沙箱网络会拒绝官方下载；使用官方 Gradle 9.5.0 发行包并记录下载环境，不能把网络失败当成代码失败。
- JDK 21 可以使用；本项目已用项目 JDK 21 完成完整构建，不得退回 Java 8 或用不兼容 Gradle 代替 Loom 要求。
- JUnit worker 曾在测试类已生成的情况下报告 `ClassNotFoundException`；改为 `verifyMapCompatibility` JVM smoke task，并让 Gradle `test` 排除该 smoke 类。
- PowerShell `-Ploader_version=0.17.3` 可能解析成 Loader `0`；使用 `run-fabric-gradle.ps1 -LoaderVersion 0.17.3 ...` 的明确参数。
- `run-fabric-gradle.ps1 clean` 会把 `clean` 误绑定为 LoaderVersion；始终先传 LoaderVersion，再传 Gradle 任务。
- `.git/index.lock`、`native-platform.dll` 和离线 Loom 依赖曾阻塞其它子模块验证；遇到时保留未验证状态，不创建伪造提交、JAR 或 Release。
- 版本发布曾出现“直接覆盖”的风险；通过新分支、新标签、外部 release 目录和 SHA-256 文件解决。
- 测试脚本名称必须使用仓库实际命令，例如 `npm run verify:fabric-data`，不要凭直觉拼接任务名。
- 只做源码/编译验证时不能声称 Minecraft 窗口和真实服务器联调已经完成。

## 11. 验收门槛

以下任一项失败都不能标记本版本为完整发布：

- 基线 JDK 21、Loader 0.17.3 下完整构建失败。
- 总控或任一子板块鼠标点击、滚轮、拖拽、聊天输入或原生返回被快捷键破坏。
- 外置模块存在时内置模块重复初始化、重复线程、重复事件或重复配置读写。
- 版本不兼容警告缺失，或地图失败导致其它模块失效。
- 诊断自动上传、泄露凭据或写入未说明目录。
- JAR 错误打包 Xaero/Mod Menu，或缺少必要的 jsoup 嵌入依赖。
- 真实客户端启动、标题/世界/容器路径和父 Screen 行为没有证据。
